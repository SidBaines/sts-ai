# Repaired environment and protected strategic learning

Authorized 12 October 2026 after the independent critique. Work stays in `codex/nonllm-critique`. Primary local CPU/GPU allocation runs until approximately **13 October 07:30 UTC**; earlier campaigns, releases, budgets and final data remain preserved. The goal is a trustworthy training setup and demonstrable progress toward full-game play. Operational checks alone cannot qualify a training condition for a longer run.

## Implementation and evidence gates

1. Publish an isolated candidate environment/interface revision. Preserve distinct combat card actions and teacher identities; expose typed public inventory/action semantics; incorporate the separately tested Discovery repair. Preserve the legacy low-level menu for historical reproduction, but reject old banks under the new core observation/provenance identity. Add transition-based mechanics, private-field and deterministic replay regressions.
2. Add a versioned richer public encoder and policy with exact card/source/target relations, enemy HP/block/intent/powers, numeric upgrade/counter/effect fields, unknown-value masks and feasible route features. Keep legal-candidate scoring and optional dependencies. Maintain explicit legacy model loading for behavior transfer; incompatible inputs must fail closed.
3. Generate fresh TRAIN banks and matched DEV definitions. Establish the original policy's new-interface baseline, then validate one common warm start using distillation or supervised fitting. Hold new final cohorts unopened during tuning. Separate isolated fights, continuation starts and fresh games.
4. Implement choice-aware phase losses, frozen-combat strategic macro collection, original-policy TRAIN rehearsal, actual sample/gradient/drift/value/reward telemetry and permanent evaluation snapshots. Match controller, sampling, RNG, horizons and objectives in micro/macro comparisons. Repair ownership publication and status/retention before unattended runs.
5. Run bounded protected OOC comparisons with multiple seeds and explicit early retention/usefulness gates. Preserve bad outcomes and diagnose them. Scale only a condition with credible retained competence and improvement; investigate representation/supervision/reward alternatives when the protected comparison is unproductive.
6. Update reporting/dashboard around full-run wins, paired gains/losses, survival/boss reach, learning diagnostics and real wall throughput. Benchmark typed encoding and persistent collection; optimize measured bottlenecks without dropping legal candidates or changing scientific settings silently.
7. Before the allocation checkpoint, stop owned training, preserve all evaluated/recovery models and prepare a clear status/handoff. Completion still requires verified scope; unfinished work remains explicit and the goal stays active for later continuation.

## Runtime boundaries

Use this worktree's independent `.venv` and native source/build. Its dependencies are copies of the existing pinned runtime; no installation or build modifies earlier worktrees. Simulator operations remain isolated and bounded. Resource checks must distinguish AC presence from a battery that is still discharging; pause with recovery data if power or storage cannot sustain the run.

Every bug fix receives a regression. Run the host/native suite with `STS_REQUIRE_SIMULATOR=1` and the required bounded random seed-3 smoke before accepting the repaired execution path. Same-seed deterministic traces must match across fresh processes under each new condition. Observation/menu, encoder, reward and model changes carry explicit identities and migration records.

The [critique](nonllm_training_critique_2026-10-12.md) provides measured motivations and caveats. This plan does not assume any numerical hyperparameter is optimal or promise mastery within one allocation.
